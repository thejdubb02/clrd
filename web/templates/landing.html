Dismiss once. Gone everywhere.

clrd is a self-hosted notification server. Send an alert with one HTTP call. It lands on your phone, your tablet and the web inbox. Clear it on any of them and it clears on all the others.

Self-host clrd Read the docs

Small on purpose: a 15.6 MB server and a 1.9 MB Android app, against 77.5 MB and 9.3 MB for ntfy (measured 2026-11-20).

In early development. The API is settling; expect changes before 1.0.

How it works

  1. Send. A script, a monitor or an AI agent posts an alert to a topic.
  2. It arrives everywhere. Every phone, tablet and browser signed in to that topic shows it, an open web inbox plays the sound you picked, and a browser with notifications turned on in Settings shows one even with clrd closed. Adding a device is one QR code scan.
  3. Clear it anywhere. Swipe it aside and tap Clear in the phone app, click Clear on the web (on a phone, swipe a card and tap Clear), or let the sender resolve it when the fault is fixed.
  4. Every device follows. The server owns the state, so the alert leaves every inbox and every phone tray.

No clocks, no conflicts

Every change is an event with a number. Each device remembers the last number it saw and asks for everything after it when it reconnects.

48211  created    backups  Nightly backup failed
48212  dismissed  backups  by pixel-9

A tablet that was off overnight asks for everything after 48211 and drops the alert before you look at it.

More than read and unread

Four things can happen to an alert, and every device sees which one did.

Cleared
You cleared it. Gone from every device.
Acknowledged
Someone is on it. It stays in the inbox and stops buzzing.
Resolved
The sender cleared it because the fault is fixed. Monitors close their own alerts by id.
Snoozed
Hidden until a time you pick, then it comes back and notifies again.
Marked
Someone else, or an agent, saw it or actioned it. The card stays put and shows who, with their note and link.

Plug it into what you already run

One HTTP call to send. One more to clear it when the problem goes away.

curl

curl -H "Authorization: Bearer $CLRD_TOKEN" \
  -d '{"topic":"infra","title":"Disk full",
       "message":"web-1 at 95%","priority":4,
       "external_id":"disk-web-1"}' \
  https://clrd.example.com/api/v1/notifications

When the disk has room again, the sender clears it everywhere:

curl -X POST -H "Authorization: Bearer $CLRD_TOKEN" \
  https://clrd.example.com/infra/disk-web-1/resolve

AI agents (MCP)

clrd serves MCP at /mcp. Agents can send, list, acknowledge and resolve, edit a progress message in place, and wait_for_reply lets an agent ask you a yes or no question and wait for your tap. With publish on a topic an agent can also set up silences, check-ins and incoming webhook templates there; with an admin token, outgoing webhooks and tokens. Claude Code and Codex can send their permission prompts to your phone through /mcp/approve. For Claude Code, the clrd plugin sets up all of it, plus a ping when a task finishes, in one install. To give an agent its own sign-in, press Add agent in Settings and hand it the one-use invite: it reaches only the topics you pick.

Already on ntfy?

Most ntfy scripts work once you point them at clrd and give them a clrd token (or import your ntfy users). What is supported is listed below.

curl -H "Authorization: Bearer $CLRD_TOKEN" \
  -H "Title: Disk full" -H "Priority: high" \
  -d "web-1 at 95%" https://clrd.example.com/infra

Supported: PUT and POST /{topic}, the Title, Priority, Tags, Click and Actions headers, JSON publish to /, and /json, /sse, /ws and /raw subscriptions with since=.

Switch from ntfy

Stop ntfy, run one command, point its hostname at clrd. Users, passwords, tk_ tokens, per-topic access rules, anonymous access, message history and attachments come across, so every script and phone keeps its credentials. Keep ntfy stopped, not deleted, and you can roll back by pointing the hostname back.

Migration guide

On Gotify? clrd import gotify brings over every app, its token and the message history, so senders keep working. Switch from Gotify

clrd import ntfy --dry-run \
  --auth-file /var/lib/ntfy/user.db \
  --cache-file /var/cache/ntfy/cache.db \
  --attachment-dir /var/cache/ntfy/attachments

Self-host it

One Go binary and one SQLite file. No Redis, no message broker, no account on anyone else's service. clrd sends no telemetry, and the only pages it fetches are site icons and link previews your devices ask for.

The only setting you need is the HTTPS address your proxy serves it on. Open the setup link it prints to make your admin token, scan the Link a phone code with the app and approve it, and send. Check-ins, webhooks, icons and snooze times are optional, and server settings, topics, tokens and webhooks are all on the REST API, so an AI agent can set them up for you.

No published image yet: the compose file builds one from the repository. Or build the binary with Go 1.24 or newer.

git clone https://github.com/thejdubb02/clrd
cd clrd
# set CLRD_BASE_URL in docker-compose.yml
docker compose up -d
docker compose logs clrd

On first start, clrd prints a one-time admin setup link to its log. It can also run under a sub-path, such as https://example.com/clrd.

The Android app

Built for F-Droid. No Google Play Services, so it runs on GrapheneOS, LineageOS and any phone without Google. It keeps one connection to your server and removes an alert from the tray the moment it is cleared anywhere else.

Notifications from one topic can stack together in the tray (off until you turn it on), Reply and link buttons work from the tray, and it trusts certificate authorities you install, so a home-lab server works over HTTPS.

Not in the main F-Droid catalog yet. Every Android change on main goes to clrd's own F-Droid repository: how to add it.

Open source

Apache 2.0. The server, the web inbox and the Android app live in one repository, built against one written contract.
